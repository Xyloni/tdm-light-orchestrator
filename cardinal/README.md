# Предпросмотр одного лота Cardinal

1. Запустите новую сборку оркестратора с переменной окружения ORCHESTRATOR_LOT_PREVIEW_TOKEN длиной не менее 32 символов. При запуске в Docker передайте переменную внутрь контейнера. Тот же токен задайте процессу Cardinal.
2. Скопируйте tdm_lot_preview.py в plugins, а пример настройки в configs/tdm-lot-preview.json в каталоге Cardinal. Укажите ID лота, игру, ID всех обещанных кампаний и путь к фактическому TXT автовыдачи. Поддерживаются по одному аккаунту на строку в полном формате оркестратора или формате логин:пароль.
3. Из корня Cardinal выполните python plugins/tdm_lot_preview.py configs/tdm-lot-preview.json или перезапустите Cardinal для запуска через BIND_TO_POST_START. Скрипт обращается к оркестратору на 127.0.0.1:8787, поэтому оба процесса должны видеть один и тот же localhost.
4. Откройте configs/tdm-lot-preview-report.json. Сопоставьте отчёт с остатком и заказами вручную. При изменении файла во время проверки повторите предпросмотр.

Отчёт различает отсутствующие в ответе Twitch награды, незабранные награды и отметки о получении. Выдачу в игре нужно подтверждать отдельно. Логин передаётся локальному оркестратору, пароль и OAuth не передаются. Оркестратор проверяет аккаунты, уже известные ему по логину.

По умолчанию дата снятия неизвестна. Можно задать verified_deadlines как список объектов с campaign_id, expires_at (ISO 8601 с часовым поясом) и source (официальная HTTPS-ссылка). Добавляйте сроки только после проверки для всего набора и остатка лота. Тогда отчёт покажет самый ранний из этих сроков минус buffer_hours.

Это режим предпросмотра. Он читает явно указанный файл. Действия с лотом, автовыдачей и возвратом аккаунтов в пул выполняются вручную.
